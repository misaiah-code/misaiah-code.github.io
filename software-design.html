Enhancement narrative

Artifact Description

The artifact I selected for this enhancement is my Weight Tracking Application, which was originally created in CS-360 Mobile Architecture and Programming in 2025. This artifact is an Android mobile application that allows users to create an account, log in, add daily weight entries, set a goal weight, view their progress, and manage notification preferences. The original version demonstrated basic mobile development skills through Android activities, SQLite database storage, user input handling, and screen navigation.

For CS-499, I enhanced this artifact by improving the application’s structure, security, validation, and data management. The enhanced version keeps the original purpose of the app but improves the way the code is organized and how user data is handled.

Summary of Changes

The enhanced version of the Weight Tracking Application includes several major improvements from the original CS-360 version. I added repository classes to separate database operations from the Android activity classes, which improved the organization and maintainability of the code. I added validation classes for login, registration, weight entries, and goal weight entries so user input is checked before being processed or stored. I improved account security by replacing plain-text password handling with salted password hashing. I also updated the database design so weight records, goal weights, and notification preferences are tied to the logged-in user. In addition, I added session management so the app can remember the current user, changed the Notifications screen into a Settings screen, and moved the Log Out option into Settings to improve the user experience.

Justification for Inclusion in the ePortfolio

I selected this artifact for my ePortfolio because it shows my growth as a software developer. The original Weight Tracking Application was a complete mobile app, but it also had areas that could be improved. Much of the original logic was handled directly inside the activity classes, which worked for the original assignment but made the application harder to maintain, test, and expand. By enhancing this artifact, I was able to show that I can review older work, identify weaknesses, and improve the design of an existing application.

The enhanced version showcases my software development skills through better separation of concerns. I added repository classes to separate database operations from the user interface, which makes the code easier to understand and update. I also added validation classes for login, registration, weight entries, and goal weight entries. This improves reliability because user input is checked before it is processed or stored.

I also improved the application’s security and data handling. The original application used a simpler approach to login credentials, while the enhanced version uses salted password hashing. I also improved the database structure so weights, goals, and notification preferences are tied to the logged-in user. This makes the application more realistic because each user’s data is handled separately. In addition, I changed the notification screen into a more general settings screen and placed the logout option there, which creates a cleaner user experience.

I included this artifact because it demonstrates several important software engineering abilities: mobile application development, database interaction, input validation, secure coding practices, refactoring, and maintainable design. The artifact was improved not only by adding functionality, but by making the internal structure stronger and more professional.

Reflection on the Enhancement Process

The process of enhancing this artifact helped me understand the importance of maintainable software design. When I originally created the app, my main focus was getting the required features working. During the enhancement process, I had to look at the project from a different perspective. Instead of only asking whether the app worked, I had to ask whether the code was organized, secure, reusable, and easy to maintain.

One important lesson I learned is that meaningful software improvements are not always visible on the screen. Some of the most important changes were behind the scenes, such as adding repositories, validation classes, password hashing, session management, and user-specific data handling. These changes may not completely change how the app looks, but they make the application stronger and more realistic.

One challenge I faced was improving the app without overcomplicating it. Since this was originally a CS-360 project, I wanted the enhanced version to still feel connected to the original artifact. I had to balance making the project more advanced with keeping it understandable and realistic. Another challenge was adjusting the layout after adding logout functionality. The original placement caused the logout button to interfere with another button, so I moved logout into a settings screen. This was a good reminder that improving software often involves both code changes and design decisions.

Overall, this enhancement helped me become more confident in refactoring and improving existing code. I learned that reviewing older work can reveal many opportunities for improvement, especially in structure, security, validation, and data handling. The final enhanced artifact better represents my current abilities as a developer and shows how I have grown since the original CS-360 assignment.
